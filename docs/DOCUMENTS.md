# Background draft lifecycle

A POST to the shipment’s `document-jobs` collection accepts a shipment version, document type and UUID idempotency key. Authorization requires both shipment read and document download, including for external collaborators. A transaction saves the exact shipment, resolved settings, settings revision, rendered HTML and HTML hash, then adds a small outbox row. The response is 202 with a durable request ID, even when Redis is unavailable. Reusing the same requester/key returns the original request; changing type, shipment or version with that key returns 409. Pending requests are bounded per requester.

The separate `npm run worker` process dispatches outbox IDs and requester IDs to BullMQ. Redis contains no shipment or document content. Postgres remains the source of truth. Workers claim a row with a fencing token and deadline, check current permissions, render with blocked external network requests and JavaScript disabled, and persist PDF bytes, SHA-256 and ready state in one transaction. A stale worker cannot finalize a newer claim. An expired lease can be reclaimed; duplicate delivery of a finished request has no effect. Render failures retry at most three times with backoff; a fresh request is needed after terminal failure. Revocation during rendering prevents file insertion. No successful file is overwritten.

History exposes the latest 50 request summaries for a shipment. Download routes check the current session and permissions, tenant and shipment binding, ready state and saved byte hash. URLs are session-protected API routes, not public object links. Older files remain unchanged after edits. Request/ready/failure/download events are audited. The database runtime role cannot alter snapshots or update/delete saved files. Outbox metadata is internal operational state, has no document contents and is never returned by an API.

PDF files are limited to 10 MiB each and stored in Postgres for this stage. This adds database storage and backup load; retention, total storage quotas and migration to private object storage are release work. A draft request is not a numbered issued document. The synchronous PDF endpoint remains for compatibility; the web app uses background jobs. Production must run and monitor the separate worker, configure Redis TLS/authentication/persistence/no-eviction and database backups, and track outbox age and terminal failures. Production deployment is not completed by this local change.

Integration coverage uses a disposable database and a uniquely named queue. It proves idempotency, optimistic versions, immutable snapshots and files, access boundaries, renderer failure exhaustion, expired-lease recovery, duplicate delivery, revocation during rendering, actual Redis/BullMQ processing and the browser download/history flow.
